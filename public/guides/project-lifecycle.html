Five phases, one hand-off rule. Analysis & Scoping covers the whole project; Design and Development run module by module. Use this page to check what happens next and what you should click.

The hand-off rule

Every piece of work goes to a reviewer, then an approver. Either can send it back with a comment.

Who does what

Project ownerSets up the plan, removes phases the project skips, adds modules, requests Start Project, keeps assignees current.
Instructional DesignerAnalysis & Scoping work and each module's storyboard.
Content DeveloperBuilds each module once its design is signed off.
Reviewer (QA)Pass QA or For Revision on every review step.
ApproverSigns off scope, design and build; approves Start Project.

Your routine, every day

  1. Open My Dashboard. Clear Waiting for you first: reviews, sign-offs and work sent back hold other people up.
  2. Go to My Tasks. Work down the Next action column: Ready, then buttons.
  3. Log time as you go (Time Tracking › Log time). Hand-offs need logged hours.
  4. Click the button and check the pop-up: Reported Completion is the day you finished, Output Count is 1 or more.

Phase order, when live

Scope first, then plan the rest, then start.
Analysis & Scoping always comes first. In Draft it's the only phase where tasks can be added and worked.
The rest opens after sign-off. Design, Development, Implementation and Evaluation stay greyed out until every scoping task is done and Scope Sign-Off is approved. The owner then plans them, still in Draft.
No scoping needed? Remove Analysis & Scoping from the project and every other phase opens straight away. The usual planning and Start Project rules still apply.
Phases can run side by side. Implementation and Evaluation don't wait for Design or Development unless a task's Depends on says so.
Who plans. The project owner, their supervisor or Full Access. Everyone else sees their tasks once the project has started (scoping assignees see theirs in Draft).
The order in short. Scope › Sign-Off › plan the other phases › Request Start Project › approved › the team sees its tasks.

Owner: setting up a project

  1. New project › name, owner, start date › Save draft & continue. The Analysis & Scoping tasks appear.
  2. Show more details and fill the 7 details needed before Start Project.
  3. Remove the phases the project doesn't need (phase ⋯ menu).
  4. Assign the scoping tasks, then Add your first module on the Design row (name; Instructional Designer and Content Developer optional).
  5. Add Implementation or Evaluation tasks from Add task › Use template.
  6. Own task that needs checking? Task ⋯ menu › Add review steps, or add a task with Work Type Quality Assurance (review) or Sign-Off (final approval). Tempo asks which task it checks and links them. Then Request Start Project.

Good to know

Draft plans are private. Only the owner's line and Full Access see the tasks, except people assigned Analysis & Scoping work.
One button, chosen for you. Once you log time, Tempo shows only the button that fits the task: Ready for Review if a Quality Assurance or Sign-Off task follows, otherwise Mark Done. The Work Type decides: Quality Assurance gets Pass QA, Sign-Off gets Approve. Setting a reviewed task to Done from the Status dropdown still sends it for review.
Done is done. To change finished work, the review step sends it back For Revision. You can't reopen it yourself.
Plan changes (names, dates, hours, assignees) are for the owner, their supervisor or Full Access. Everyone updates their own status and completion.
Group by Module on the WBS shows each module's whole chain. Milestones stay on the phases.
